# S10 cursor-agent headless on Windows

Question: does `cursor-agent` run headless in a git worktree, and can a per-worktree permission file stop writes outside the allowed paths?

CLI: `cursor-agent` 2026.10.22-27dcf5f. Throwaway repo and worktree under the temp directory. Permission file `<worktree>/.cursor/cli.json` allowed `Write(allowed.txt)` and denied `Write(forbidden.txt)` and `Shell(**)`.

Flags that matter:

- Print mode: `--print`
- Output format: `--output-format json` (`text` and `stream-json` also exist)
- Model: `--model <name>` (omitted here; the account default was used)
- Non-interactive trust: `--trust`
- Workspace: `--workspace <worktree>` with the process cwd set to the same worktree
- Unprompted tool use: `--force` (alias `--yolo`)
- Sandbox: `--sandbox disabled` for this measurement

Both the no-`--force` run and the `--force` run exited 0 in about 30 seconds, wrote `allowed.txt` in the worktree, included a `usage` object (`inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`), wrote `forbidden.txt` anyway, and wrote a file at an absolute path outside the worktree.

The permission file is not a boundary. Headless mode itself works and reports usage.

Result: FALLBACK hard timeout and process-tree kill; scope diff and proofs instead of permission file
